## What shipped
- **Atomic state advance on validation save** — completing a full validation now does everything in one move: status pill → emerald **Delivery Validated** (previously stopped at "Delivered"), stepper marks Delivery Validation done (fixed labels, date fills in) with Invoice Submission (VENDOR) next in sky "in progress", and a violet **Receipt of Goods #ROG-{n}** doc-row is appended to Documents. The validation *is* the ROG — the document is generated by the save, never uploaded.
- **Confirmation strip** — the Next-Task Strip flips to: emerald flag icon, "Delivery Confirmed · You have confirmed receipt of all items", a sky **"Awaiting vendor invoice"** pill (whose-turn color — the ball is in the vendor's court), and **Write a Review** (outline, star icon) as the one remaining buyer action. This is the user-requested "next action = awaiting invoice upload from the vendor".
- **Documents awaiting note** — below the doc-rows, a quiet clock note: "**Awaiting vendor invoice** · The vendor has not uploaded an invoice yet." Shown only when the order is fully validated and no invoice document exists yet.
- **Seeded Order #674** matching the reference (Bayou Crossing, one Vinyl Cordless Plus Mini Blind $30.40 + $11.99 shipping = $42.39, placed Aug 28 10:42 AM, PO + ROG docs, activity with "Delivery validated · Purchase order receipt confirmed" and a Show-3-more collapse).
- **Rail property now data-driven** — the Customer card's Property/Shipping rows previously hard-coded Magnolia Place; orders now carry a `prop` id resolved against the property list (avatar initials derived), so #674 correctly shows Bayou Crossing / 3850 Airline Dr.
- **Tracking-table home for the state** — #674 seeded in the Open tab: emerald "Delivery Validated" fulfillment pill, no attention tint, overflow menu instead of the Validate primary (validated rows have no Validate action), ranked past Delivered in fulfillment sort; one generated filler row dropped so the Delivered card stays at 8 and Total Open at 62.
- **ROG in the audit trail** — the live save now logs "Receipt of Goods generated · #ROG-{n} added to documents" beneath the "Delivery validated" entry, and the generated ROG carries the validation date (doc rows previously derived every date from the placed date).
- **Claims count toward completion** — completion is now received + claimed ≥ ordered (not received alone), so an order with claim-canceled units can still reach Delivery Validated instead of being stuck offering Start Delivery Validation forever. When a claim covers part of the order the strip stays honest: "All items are received or covered by a claim." The rose claim callout remains in the rail — delivery is resolved; the claim is a parallel exception.
- **Strip wraps on narrow widths** — new `max-width: 860px` rule lets the task strip wrap (pill + button drop below the text) instead of crushing the body to one word per line.

## Claim window rule (follow-up decision)
The buyer's right to claim ends with the buyer's own attestation, never the vendor's action: claims open at order placement, survive delivery validation **and** invoice submission, and close when the buyer **validates the invoice** — approving an invoice and claiming its units shouldn't be billed are contradictory acts. An open claim holds the invoice, so claims resolve before invoice validation; raising one during invoice review is a first-class entry. After invoice validation a problem is a **return/warranty** issue (different vendor-mediated flow, no billing hold — named gap, not designed). Enforced: order-detail item links hide once `prog.done ≥ 6`; the tracking table's row menu shows "Report an issue" only where the window is open (open-validated rows yes, invoice-validated/paid/closed rows no). Codified in the design doc's Buyer Order Detail claims rule + Lifecycle Matrix attestation note + the gallery Claim Modal card.

## Deviations from the reference (system rules applied)
1. **No "Validate Invoice" primary button.** The reference shows it enabled while simultaneously saying no invoice has been uploaded — a primary action that cannot be performed. It appears only once an invoice document exists (the Invoice Validation step, next view).
2. **No strip "Raise Claim" button** — claims live where they're discovered; the item-level "Report a problem" links remain the entry (established declutter rule).
3. **One status pill** — the reference shows header "Delivered" + progress "Delivery Validated"; we advance the single pill to Delivery Validated (state expressed once).
4. **Doc-rows keep the spec** — ghost download row-action per the Shared Rail Primitives table, not the reference's View/Export text links + "Export all"; PO stays sky-tinted (reference shows emerald), ROG violet per the tint map.
5. **Fixed stepper labels** — step 4 stays "Delivery Validation" with its date; the reference renames it "Delivery Validated" when done.
